# Лабораторная 3

## Отрабатываемый материал

Observability, авторизация

## Задание

- Добавить привязку счетов к пользователю
    - Добавить user_id к счетам (нуллабельная колонка)
    - Написать datafix (sql запрос, проставляющий нужные данные), параметризированный айди счетов и айди пользователей
    - Приложить datafix в папке sql (в корне репозитория)
    - Добавить миграцию, проставляющую колонке user_id notnull констрейнт
- Добавить авторизацию через JWT токены на гейтвее
    - Интегрировать с Keycloak
    - Передавать user_id в запросах grpc (явным полем)
    - При первой авторизации пользователя, информация о нём должна быть записана БД
- Создание счетов доступно только пользователям с ролью admin
    - Создание счетов должно подразумевать привязку счёта к конкретному пользователю
    - Пользователь не может иметь более 5 счетов
- Все операции над счётом должны принимать account_id
    - В бизнес логике должны быть проверки принадлежности счёта текущему пользователю
- Пользователи с ролью admin также могут иметь счета
- Добавить структурное логгирование в операции бизнес логики
- Добавить трейсинг в методах бизнес логики
    - Трейсы должны быть распределёнными
    - Трейсы должны передавать user_id и account_id (где они есть) как теги
    - Теги user_id и account_id должны присутствовать на всех дочерних спанах и в логах
- Добавить метрики бизнес операций
    - Создание счёта
    - Снятие/получения
    - Создание/оплаты/отмены инвойсов
- Добавить оркестрацию сервисов через Aspire
    - Контейнеры сервисов должны быть созданы в Aspire
    - Вся телеметрия должна отображаться в дэшборде Aspire
