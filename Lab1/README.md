# Лабораторная 1

## Отрабатываемый материал

Основы .NET, async, Npgsql, ASP.NET.

## Цель

Освоить основы .NET, поработать с ASP.NET, отработать механизмы клиент/серверного взаимодействия.

## Задание

Дополнить сервис из [lab-5](https://github.com/Shapka11/OOP-Design-Patterns-Hub) по ООП реальной
интеграцией с БД, реализовать к нему консольный клиент.

## Не функциональные требования

- Реализация должна сохранять гексагональную структуру из lab-5
- Реализация должна использовать PostgreSQL в качестве хранилища данных
    - Для развертывания БД следует использовать Docker
- Реализация persistence слоя должна использовать Npgsql
    - Для реализации миграций необходимо использовать FluentMigrator и SQL код для описания самих миграций
- Реализация репозиториев должна использовать async и IAsyncEnumerable
- Все необходимые конфигурации (системный пароль, подключение к БД) должны использовать IConfiguration и IOptions
    - Необходимо использовать валидации для опшенов
- Реализации сервисов должны использовать async
- Реализация presentation слоя должна быть переделана согласно REST
    - Сервис должен отдавать OpenAPI спецификацию
    - Сервис должен иметь настроенный Scalar UI / SwaggerUI
- Реализация presentation слоя должна содержать валидации всех поступающих запросов
- Реализация консольного клиента должна использовать [`Spectre.Console`](https://spectreconsole.net)
    - Консольное приложение должно быть интерактивным
    - Должен быть цикл в котором обрабатывается пользовательский ввод
    - Нет необходимости реализовывать парсинг команд вручную, можно
      воспользоваться [функционалом библиотеки](https://spectreconsole.net/cli/tutorials/quick-start-your-first-cli-app),
      вызывая его в цикле
    - Функционал логина должен сохранять идентификатор сессии
- Реализация серверного взаимодействия должна использовать Refit для генерации клиентов
    - Необходимо вручную обрабатывать коды ответов (используя `IApiResponse<>`), а не использовать исключения
- Реализация клиентского приложения должна соответствовать гексагональной архитектуре
    - Используйте DI для связки сервисов

## ВАЖНО

При копировании кода из репозитория ООП или при создании новых проектов – следите за соответсвием структуры solution
папок и файловой системы. Зачастую Rider может создавать проекты в корне репозитория, что нежелательно и вызывает
проблемы при ревью кода.
Это касается и последующих лабораторных.

Для выполнения работы, создайте папки `service` и `console-client` в папке `src` (в solution и на ФС), в каждой из них,
соответственно, размещайте необходимый код.
